## Architectural compliance

1. **Graph lifecycle wiring**: Candidate registration and evidence eligibility are wired directly into the actual graph lifecycle via [`evaluate_candidates_node`](file:///home/swyra/projects/travel-agent/backend/src/functions/orchestrator/graphs/trip_planner/graph.py#L162-L280) on [`TripPlanningNode.EVALUATE_CANDIDATES`](file:///home/swyra/projects/travel-agent/backend/src/functions/orchestrator/graphs/trip_planner/graph.py#L114). The scheduler strictly consumes the gate output. Verified brief destinations are distinguished from unverified proposals, and a safe path is defined when gate output is missing so unverified proposals never reach the scheduler.
2. **Honest existence evidence links**: Existence is never inferred from a casual name mention, url substring, missing support type, unavailable page, NEEDS_BROWSER placeholder, stale observation, or unrelated claim category. Positive existence verification requires a fresh, verified claim in an existence category ([`ClaimCategory.ATTRACTION`](file:///home/swyra/projects/travel-agent/backend/src/functions/orchestrator/evidence/schemas.py#L35), EXISTENCE, LODGING, TRANSIT) with an explicit [`ClaimEvidenceModel`](file:///home/swyra/projects/travel-agent/backend/src/functions/orchestrator/evidence/models.py#L126-L158) link having support type SUPPORTS to an active, valid, non error, fresh source observation.
3. **Owner to execution authorization**: Owner to execution authorization is verified at the evidence boundary. When a caller supplies another owner real execution ID in PostgreSQL or memory fixtures, [`DeterministicEvidenceEligibilityGate`](file:///home/swyra/projects/travel-agent/backend/src/functions/orchestrator/evidence/eligibility.py#L75) raises a PermissionError.
4. **Spatial candidate resolution**: Name only provider identity matching has been replaced. Proposals are matched against existing records using spatial proximity within 100 meters and name similarity threshold of 0.8. Same named places located far apart remain distinct canonical records, while replay of the same candidate resolves to the existing place without creating duplicates.
5. **Preserved scheduler windows and labels**: Verified and assumed opening windows pass through the scheduler interface and are preserved on [`ScheduledStop`](file:///home/swyra/projects/travel-agent/backend/src/functions/optimizer/solver.py#L32-L46) with accurate labels (`HOURS_ASSUMED` or `VERIFIED_HOURS`).
