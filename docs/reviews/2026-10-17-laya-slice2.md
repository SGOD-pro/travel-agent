## Summary
This change implements Slice 2 of the remote LAYA decision router conforming to specification 0004. ## Strengths
- **Dual authentication header separation**: Cleanly attaches `Authorization: Bearer {LAYA_API_KEY}` and Cloudflare Access tokens `CF-Access-Client-Id` and `CF-Access-Client-Secret` without coupling or hardcoding credentials.
- **Robust deadline and retry semantics**: Tracks cumulative elapsed wall clock time across attempts against `LAYA_TOTAL_DEADLINE_SECONDS`, preventing runaway retry loops while dynamically calculating socket timeouts for each attempt via `min(socket_timeout, remaining_deadline)`.
- **Fast failure on client errors and unconfigured URLs**: Fails fast with zero retries on HTTP 4xx responses (`FALLBACK_ERROR`) and unconfigured endpoints (`FALLBACK_UNCONFIGURED`), avoiding wasted retry delays when client configuration is missing or unauthorized.
- **Deterministic singleton bypass in client**: When exactly one choice is eligible, `query_decision` immediately returns a deterministic singleton decision with status `DETERMINISTIC_SINGLETON`, null confidences, and latency 0 ms without issuing outbound HTTP requests.
- **Comprehensive payload sanitization**: `sanitize_context` filters traveler personal data (names, emails, phone numbers, auth tokens) before wire payload creation, while `sanitize_headers` and `sanitize_text` redact secrets from telemetry and logs.
- **Strict mode missing field resolution**: Resolves missing `answer_confidence` deterministically from top choice probability, preserves `confidence` as null, falls back to root model versions, and records omitted tokenization metadata as unknown truncation without assuming full context proof.
