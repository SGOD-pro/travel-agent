## Summary

This change set resolves the production evidence dispatch and adapter wiring requirements for spec 0002. It eliminates the synthetic echo success executor stub from the orchestrator registry, establishes dedicated single ownership of task claim and completion in EvidenceCollectorService, wires live SerpApi and Scrapling adapters into the runtime path, and ensures missing credentials produce explicit unavailable source records instead of silent successes or fake evidence. A comprehensive offline regression suite verifies database persistence and fencing behavior on live PostgreSQL.

## Minor

### 🟡 Search query exception isolation vs task level failure, `backend/src/functions/evidence_collector/service.py:524`
**Problem**: In `execute_collection_task`, the search loop specifically catches `SerpApiAdapterError` to populate `unavailable_sources`, whereas the web extraction loop catches all general `Exception` instances. Any unexpected exception from a search provider not subclassing `SerpApiAdapterError` escapes to the outer handler and fence fails the task.
**Why it matters**: While the built in `SerpApiAdapter` wraps HTTP and timeout errors into `SerpApiAdapterError`, alternative or future search adapters that raise standard library or third party exceptions would trigger an immediate task failure instead of recording partial progress in `unavailable_sources`.
**Suggested fix**: Catch general exceptions or define a unified provider exception hierarchy for search queries, matching the resilience pattern used in the web extraction loop.

## Strengths

* Single owner claim and completion: By delegating evidence tasks directly to the dedicated evidence collector consumer, the change prevents duplicate claims or conflicting completion calls between the orchestrator worker loop and the collector service.
* Elimination of synthetic echo stubs: Removing the default echo executor from `EXECUTOR_REGISTRY` guarantees that unregistered actions fail explicitly with `WorkerNotImplementedError` rather than fabricating success.
* Fail fast configuration checks: When `SERPAPI_API_KEY` is absent, the service generates explicit `UNAVAILABLE` records in `unavailable_sources` without initiating outbound network calls or fabricating mock observations.
* High fidelity offline regression: `test_evidence_dispatch_regression.py` validates the entire dispatch envelope against live PostgreSQL tables, verifying immutable record insertion into `source_observations` and lease token invalidation upon completion.
