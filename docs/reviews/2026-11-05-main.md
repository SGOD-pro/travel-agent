## Summary
This change integrates real hosted providers into the LangGraph trip planning workflow across two bounded phases. Step A introduces a boto3 Bedrock adapter implementing `HostedLlmClientPort` with configurable model identification, region settings, bounded timeouts, local AWS profile selection (`AWS_PROFILE=aws`), cross region inference profile auto retry (`apac.amazon.nova-lite-v1:0` on on-demand `ValidationException`), and safe thread offloading in async execution. Step B wires the existing `WeatherClientPort` directly into the orchestrator graph after route consumption, sampling meteorological metrics along the corridor with exact stop arrival and departure timestamps, preserving 16 day forecast horizon boundaries, severe monsoon and ghat warnings, Open Meteo provider attribution ("Weather data by Open Meteo.com"), and graceful fail soft degradation when providers experience outages or when routing fails closed.

## Strengths
* Clean adherence to hexagonal ports and adapters: `BedrockLlmClient` implements `HostedLlmClientPort` and `OpenMeteoWeatherClient` implements `WeatherClientPort` without coupling the LangGraph state machine to provider SDK internals.
* Robust boundary and invariant enforcement: generative proposals never bypass deterministic evidence gates or get marked as verified places without supporting source claims.
* Fail soft resiliency: neither LLM outages nor weather API timeouts crash the planning workflow; the graph records honest diagnostics in `provider_diagnostics` and delivers an inspectable proposal with available details.
* Zero straight line guesswork: when routing fails closed or is unavailable, the weather evaluator samples points at local midday without fabricating road arrival times, preserving genuine meteorological conditions.
