## Summary
This review confirms the resolution of source identity contamination and false evidence promotion in Slice 8A. Previously, when the evidence worker performed web scraping on a URL selected from search results, the search query title was copied into the scraped observation title metadata. Claim ingestion then read this copied title, which treated the search result title as if the page itself declared that identity, leading to unwarranted SUPPORTS links and promotion of unrelated pages.

The fix cleanly isolates search origin metadata (`search_selected_title`) from page extracted identity (`page_title`). The scraper derives page title strictly from HTML content elements (`<h1>` or `<title>`), never falling back to search query strings. Claim ingestion exclusively examines page content keys (`page_title`, `title`, `name`, `place_name`, `property_name`) and ignores `search_selected_title`.

In addition, entity matching is decoupled from closed status. When an observation reports a venue as closed or defunct, a closed claim is recorded. When both supporting and refuting observations exist for a candidate, both claims are ingested, allowing the deterministic claim policy to detect the contradiction and preserve both claims as CONFLICTED and the candidate as CONTRADICTED.

## Findings Status

### RESOLVED: Search origin metadata isolated from page extracted identity
In `backend/src/functions/evidence_collector/scrape.py`, `page_title` is extracted strictly from the document structure and never defaults to the search title. The search title is preserved separately as `search_selected_title`. In `backend/src/functions/evidence_collector/service.py`, forced assignment of `ext_art["title"] = page_title` has been removed. In `backend/src/functions/orchestrator/evidence/claim_ingestion.py`, observation title extraction explicitly skips `search_selected_title`.

### RESOLVED: Unrelated and ambiguous pages remain unverified
When a search result points to an unrelated page, claim ingestion produces zero SUPPORTS links for the candidate. When a page lacks identity evidence, the candidate remains UNVERIFIED.

### RESOLVED: Contradictory evidence preserved honestly
When search results assert active status but scraped content asserts permanent closure, both claims are ingested. The deterministic policy detects the status mismatch and marks the claims CONFLICTED, evaluating the candidate as CONTRADICTED without suppressing the conflict.

### RESOLVED: Honest browser fallback status reporting
Browser fallback remains recorded as PENDING because static extraction succeeded and emitted no dynamic rendering requirement.

### RESOLVED: Connected acceptance test provenance proof
The connected acceptance test on isolated PostgreSQL proves real page content extraction (1000 characters of Bengali text), confirms isolation of search selected title from page title, verifies that non matching page content generates zero false SUPPORTS links, and confirms that candidate stops in `eligible_stops` are backed by genuine search observations.
