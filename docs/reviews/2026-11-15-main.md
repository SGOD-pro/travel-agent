## Verification of Requirements

### 1. Removal of Hardcoded Dish Fallback and Honest Status Reporting

In `backend/src/functions/orchestrator/graphs/trip_planner/graph.py`, the previous fallback that injected hardcoded Kolkata dishes (Kathi Roll, Rosogolla, Macher Jhol) whenever observation lists were empty has been deleted.

The status computation now strictly evaluates evidence presence:
1. If both regional dishes and dining venues are missing, status evaluates to UNAVAILABLE with an informative diagnostic reason string.
2. If dining venues exist without regional dishes, status evaluates to PARTIAL with an informative diagnostic reason string.
3. If regional dishes exist without dining venues, status evaluates to PARTIAL with an informative diagnostic reason string.
4. Status evaluates to COMPLETED only when both dimensions are populated from source backed evidence.
5. In addition, culinary dish names are filtered out from candidate stops so that food items cannot leak into dining recommendations.

### 2. Dish Extraction Provenance and Sentence Sourced Descriptions

In `backend/src/functions/orchestrator/evidence/place_extraction.py`, `PlaceExtractionService.extract_local_dishes_from_observations` has been refactored to eliminate canned regional catalogs:
1. Canned descriptions have been removed. Descriptions are extracted directly from matching sentences within the raw observation excerpt text.
2. Forced regional prefixes have been removed. A dish such as Biryani retains its base name Biryani unless the regional modifier such as Kolkata Biryani was explicitly present in the source text.
3. Every published dish dictionary includes `observation_id`, `source_url`, `retrieval_time`, and `description`.
4. Observations lacking excerpt text or lacking a source URL are rejected immediately.

### 3. Accommodation Pricing Integrity

In `backend/src/functions/orchestrator/evidence/claim_ingestion.py` and `graph.py`, lodging claims and research structures enforce strict evidence requirements:
1. In `claim_ingestion.py`, lodging claims assign `evidence_class = INDICATIVE_SEARCH` and `is_indicative_search = True` only when both a valid price and currency exist on the observation artifact. When missing, `evidence_class` is set to None, `price_per_night` is set to None, `currency` is set to None, and `is_indicative_search` is set to False.
2. In `graph.py`, `_find_matching_priced_obs` verifies hotel candidates against raw observations in the execution state. If a candidate hotel does not match an observation with both price and currency, the output dictionary sets `price_per_night = None`, `currency = None`, `evidence_class = None`, `is_indicative_search = False`, `availability_status = "PRICE_UNAVAILABLE"`, `uncertainty = "UNVERIFIED"`, and appends `price_unsupported_by_source` to `unavailable_details`.
3. Accommodation research sets overall status to UNAVAILABLE when no lodging options exist, PARTIAL when options exist without source supported rates, and COMPLETED only when supported rates exist.
4. Genuine indicative rates preserve unverified room availability and unconfirmed booking notices without asserting cheapest hotel guarantees.

### 4. Strengthened Connected Test Assertions

In `backend/tests/integration/test_trip_planner_evidence_connected.py`, assertions for connected acceptance have been strengthened:
1. Each local dish is cross referenced against `persisted_obs_by_id`. The test asserts that `observation_id` is present, exists in persisted database observations, matches the source URL, and has a description extracted from the observation excerpt text.
2. Each indicative lodging option with a price asserts that a matching observation exists with identical price and currency. Options lacking source price assert `price_per_night is None`, `currency is None`, `evidence_class is None`, `is_indicative_search is False`, and `availability_status == "PRICE_UNAVAILABLE"`.
3. Both pending gates remain honestly asserted: `browser_fallback_status` is asserted to equal PENDING when no scraped target emits dynamic rendering requirements, and scraped page provenance remains unverified without false supports promotion.

### 5. Focused Regressions in Claim Ingestion Suite

In `backend/tests/integration/test_claim_ingestion.py`, five targeted integration tests verify the corrected behaviors on PostgreSQL:
1. `test_food_and_accommodation_research_no_evidence_returns_unavailable_not_completed`: Proves that empty state returns UNAVAILABLE status with informative reasons, never COMPLETED.
2. `test_food_and_accommodation_research_provider_failure_returns_unavailable`: Proves that upstream collection failures return UNAVAILABLE status with informative diagnostic reasons.
3. `test_unsupported_candidate_price_kept_unknown_not_labeled_indicative_search`: Proves that candidate hotels with synthetic price estimates not found in source observations are preserved as PRICE_UNAVAILABLE with None pricing.
4. `test_valid_source_backed_dish_preserves_source_provenance_without_region_override`: Proves that Biryani is not overridden to Kolkata Biryani unless Kolkata appears in the excerpt, and verifies that observation ID, source URL, and sentence excerpts are preserved.
5. `test_valid_indicative_lodging_rate_labeled_indicative_search_with_unconfirmed_booking`: Proves that an observation with valid price and currency correctly produces an INDICATIVE_SEARCH claim and proposal option with unconfirmed booking status.
