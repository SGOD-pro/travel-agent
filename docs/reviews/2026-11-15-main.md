## Verification of Requirements

### 1. Distinct Property Modifier Protection and Substring Prevention

In `backend/src/functions/orchestrator/graphs/trip_planner/graph.py`, `_build_accommodation_research` defines `distinct_property_modifiers`:
1. When comparing candidate tokens and observation tokens, if either side contains a distinct property modifier (such as annex, wing, tower, suites, resort, residency, etc.) not shared by the other, substring sharing is forbidden immediately.
2. For non modifier token differences, matching is permitted only when one name is a strict subset of the other, both candidate and observation have coordinates, and haversine distance is within 1.0 km.
3. Self contained observations without separate candidates are processed directly from their own artifact reference without substring cross matching.

### 2. Spatial Bounds Verification for Same Named Properties

In `graph.py`, location identity is strictly verified:
1. When both candidate and observation have coordinates, haversine distance must be within 1.0 km. Distant locations (e.g. Kolkata vs Delhi branches) are rejected immediately.
2. When the candidate has coordinates but the observation lacks location evidence, explicit provenance is required: either the observation source URL matches the candidate source URLs, or the observation ID matches candidate observation IDs.
3. Ambiguous property matches leave the candidate preserved with `price_per_night = None`, `currency = None`, `evidence_class = None`, `is_indicative_search = False`, and `availability_status = "PRICE_UNAVAILABLE"`.

### 3. Usable Source URL Enforcement

In `claim_ingestion.py` and `graph.py`, observations must carry a usable HTTP or HTTPS source URL to produce indicative rates:
1. In `claim_ingestion.py`, `has_usable_url` checks that `obs_url` starts with `http://` or `https://`. Missing or placeholder URN URLs evaluate to `has_valid_indicative_price = False`.
2. In `graph.py`, observations without usable source URLs are skipped by `_find_matching_priced_obs` and excluded from indicative price promotion.

### 4. Full Field Attachment and Traceability

In `claim_ingestion.py` and `graph.py`:
1. Lodging claims attach `observation_id` and `source_url` in `typed_value`.
2. In `graph.py`, `indicative_options` attach `observation_id`, `source_url`, `source_urls`, `retrieval_time`, `currency`, `is_indicative_search`, `is_verified_offer = False`, `booking_confirmed = False`, and `availability_status = "INDICATIVE_SEARCH_ONLY"`.

### 5. Regressions Through Actual Proposal Path

In `backend/tests/integration/test_claim_ingestion.py`, five focused tests verify the proposal path via `synthesize_proposal_node(state)`:
1. `test_accommodation_price_attribution_rejects_similar_different_property_names`: Hotel Green Palace does not inherit price from Hotel Green Palace Annex.
2. `test_accommodation_price_attribution_rejects_same_name_at_distant_locations`: Grand Heritage Hotel in Kolkata does not inherit price from Grand Heritage Hotel in New Delhi.
3. `test_accommodation_price_attribution_rejects_missing_source_url`: Boutique Residency Kolkata without usable source URL produces no indicative rate.
4. `test_accommodation_price_attribution_valid_matching_property_and_source_backed_rate`: The Lalit Great Eastern Kolkata preserves 7500 INR rate with observation ID, source URL, and pricing notices.
5. `test_accommodation_price_attribution_unsupported_candidate_price`: Victoria Guest House with synthetic estimate and no supporting observations stays PRICE_UNAVAILABLE.

### 6. Strengthened Connected Test Assertions

In `backend/tests/integration/test_trip_planner_evidence_connected.py`:
1. Each priced indicative option asserts that `observation_id` is present and exists in `persisted_obs_by_id`.
2. The supporting observation is checked for matching price, matching currency, usable source URL, and matching property title.
